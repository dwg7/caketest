# 0003: 探索的アプローチへの転換

* ステータス: **承認(Accepted)**
* 日付: 2026-09-22
* 前提: [`0002-stage3-judgment-materials.md`](0002-stage3-judgment-materials.md)
  で整理した軸A(OSMデータ)/軸B(Layercake技術)の判断材料を受けて、
  人から示された一連の決定をまとめる

## 決定事項

### 1. 軸B(技術)は採用可、確定

Layercakeという配布技術は、認証不要のリモートクエリ・スキーマ正規化・
実測での鮮度(数日単位)いずれも良好であり、採用してよいという判断が
確定した。以後、軸Bを覆す新たな材料が出ない限り、技術選定としての
議論は再燃させない。

### 2. 低密度地域(ジュバ・フリータウン)も対象であり続ける——探索的アプローチへの転換

段階1・2では「HOT文書が課題視した低密度地域では、Layercakeも同じ
課題を引き継ぐだけで解決しない」という結論だった。この結論自体は
覆らないが、**人からの指示により、caketestの立ち位置を転換する**:

> 課題を解決しなくとも対象とし続ければ、反転させてマッピングの
> 必要をあぶり出すことになる。それが探索的アプローチだ。

つまり、「Layercakeが集落名辞書として実用に足るかどうかを判定する
プロジェクト」から、「Layercakeという窓を通じて、各国・各地域の
OSMマッピングの疎密・偏りそのものを可視化し、そこにある課題の
多様性を理解する探索的調査プロジェクト」へと重心を移す。

* データが疎であることは「失敗」ではなく、「その地域でOSM
  マッピングが必要とされているシグナル」として積極的に記録する。
* したがって、今後の地域選定でも低密度地域を排除しない。むしろ
  意図的に多様な密度・多様な国の地域を対象に含める。

### 3. ライセンス: 混在方針を明示、CC0純化にはこだわらない

「私たちのものはCC0、ODbLのものはODbL」と明示して整理する方針を
確定。詳細は[`0001-odbl-license-handling.md`](0001-odbl-license-handling.md)
の追記を参照。段階3の統合を当面見送る(下記4)ため、この方針の
実地検証(統合先での適用)は先送りになるが、caketest内部での
記録・引用の扱いには直ちに適用する。

### 4. 調査対象地域を拡張: 国家測量研修の対象国全体の特徴的な都市へ

国家測量研修の教材化を視野に、対象国全体の特徴的な都市(首都・
地方中心都市等)へ調査範囲を拡張してよい、という許可が出た。

* **対象国リストが判明(2026-09-22追記)**: [UNopenGIS/7 issue #976
  comment](https://github.com/UNopenGIS/7/issues/976#issuecomment-5709724004)
  に、JICA課題別研修「国家測量事業計画・管理」の参加9カ国が記載
  されている——フィジー、ガボン、ラオス、ナイジェリア、
  パプアニューギニア、ルワンダ、シエラレオネ、東ティモール、
  トーゴ。うちラオス(ビエンチャン)・シエラレオネ(フリータウン)は
  段階1・2ですでに検証済み。残り7カ国の首都圏は段階4として検証
  済み(詳細は[`notes/findings.md`](../../notes/findings.md)の
  「段階4」節)。
* 拡張の際は、既存の4地域(北海道・ビエンチャン・ジュバ・
  フリータウン)と同じ形式(Settlements/POIs/Highways/Boundariesの
  4レイヤー、`queries/<layer>-<地域>.sql` + `notes/findings.md`
  への追記)を踏襲する。
* **教訓(段階4で発覚)**: Highways/Boundariesのbbox判定に、面データ
  (行政境界)に対する近似の誤りがあった。狭い首都圏bboxでは
  境界ポリゴンのbboxとの「左下座標一致」判定が事実上運任せになり、
  さらに矩形重なり判定に直しても島嶼・分散国土国では遠方の無関係な
  行政区分を誤検出する問題が起きた。最終的に`ST_Contains`による
  実ジオメトリでの判定に修正した。詳細は
  [`queries/boundaries-jica-capitals.sql`](../../queries/boundaries-jica-capitals.sql)
  の注記、および`notes/findings.md`の「方法論の訂正」節を参照。
  今後、面データを新地域で扱う際は最初から`ST_Contains`を使うこと。
* 「うまくいけば国家測量研修のネタになるかもしれない」という
  位置づけであり、教材化そのものはこのADRの決定事項ではなく、
  今後の探索の副産物として期待されているもの。

### 5. 既存プロジェクトへの統合は当面考えない

kikimimi・rpi-geoserver0・zukaku・国家測量研修プロジェクトへの
実統合は、当面見送る。段階3の「実用可否の判断・統合提案」という
ロードマップ項目は取り下げず残すが、優先度を下げ、上記2の探索的
調査を優先する。

### 6. 将来的な方向性(メモ、未着手): ブラウザでの対話的プレゼンテーション

魅力的な将来像として、以下の二層構成が示された:

> Unixで対話的に研究をして、プレゼンテーションはブラウザでできる。
> どちらもデータはUSのLayercakeからオンラインで取るという世界観。

* **研究層**: 現状どおり、Unix上のDuckDB CLIで対話的にクエリし、
  `queries/*.sql`・`notes/findings.md`に記録する。
* **発表層**: ブラウザ上でDuckDB-WASM等を用い、Layercakeの
  parquetファイルへ直接(ダウンロードなしで)ライブクエリする
  プレゼンテーション/ダッシュボードを構築する構想。
* 両層とも「データはLayercake(OSM US)からオンラインで取得し、
  ローカル複製を作らない」という一貫した方針を保てるため、ODbL
  対応(案A: クエリのみ・再配布なし)とも相性が良い。
* このADRの時点では**構想・メモの段階**であり、技術選定・実装
  着手はしていない。着手する場合は改めてADRを起こす。
